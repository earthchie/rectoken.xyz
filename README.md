# RECTOKEN.xyz

Redesigned website for **REC Token** by BlockEdge Co., Ltd. - a utility token backed 1:1 by
verified I-RECs on the ThaiFi network.

The site is an Astro build with bilingual routing (`/en`, `/th`), Pagefind full-text search, light
and dark themes, live on-chain data, and a MetaMask wallet layer. A Cloudflare Worker alongside the
static assets accepts redemption requests, verifies the referenced on-chain transfer, and stores the
request in D1.

## Stack

| Layer | Choice |
|---|---|
| Framework | Astro 6 (static output) |
| Styling | Tailwind CSS 4 + a CSS-variable design system |
| Search | Pagefind 1.6 (custom UI, locale-filtered) |
| OG images | Satori + Resvg, generated by `npm run og` |
| Wallet | Injected EIP-1193 provider (MetaMask), no wallet SDK |
| On-chain reads | Direct JSON-RPC (`rpc.thaifi.com`, `mainnet.optimism.io`) |
| Redemption intake | Cloudflare Worker + D1 (`POST /api/redemptions`) |

## Quick start

```bash
npm install
npm run dev          # http://localhost:4321 - use /en/ or /th/, never /
npm run build        # astro build + pagefind + copy index into public/
npm run preview      # preview the production build
```

Search needs a built index. The first `npm run build` populates `public/pagefind`, which `astro dev`
also serves. Before the first build, the search panel shows a notice instead of results.

### Adding a long-form page

1. Add a `PageDoc` entry to `src/data/content.ts`.
2. The catch-all routes `src/pages/{en,th}/[...slug].astro` generate it automatically.
3. Add it to `NAVIGATION` in `src/data/site.ts` if it belongs in the header, and to `Footer.astro`
   if it belongs in the footer.
4. Run `npm run i18n` and `npm run build`.

### Adding a project

`https://asset.blockedge.co/rec-hydro.json` is the source of truth. The project pages call
`loadProjects()` from `src/scripts/data.ts` at build time: it reads the address list, then each
project's metadata from `https://asset.blockedge.co/<address>.json`, then the on-chain supply
from ThaiFi. The same function runs again in the browser to refresh supplies.

A new project appears on the home page, the projects page and the data page on the next build,
without editing any TypeScript. `src/data/projects.json` is only the fallback snapshot used when
the remote registry cannot be reached; regenerate it from the live JSON rather than hand-editing
it. Remove an address from `rec-hydro.json` and it disappears from the site on the next build.
Only tokenised projects belong in that list; inventory held in REHASH but not tokenised is not
published as a project.

### Adding a UI string

Add the key to **both** `src/i18n/en.json` and `src/i18n/th.json`. Use `t('section.key', locale)`.
`npm run i18n` fails on a missing or empty key.

## Design system

- Tokens live in `src/styles/base.css` (`:root` light, `[data-theme='dark']` dark). Every component
  reads `var(--color-*)` / `var(--surface)` / `var(--ink)`; there are no hard-coded theme colours.
- Fonts: IBM Plex Sans Thai across body, display and mono labels (Thai and Latin share one
  vertical rhythm); JetBrains Mono only for pure Latin data such as addresses and contract IDs.
  Root is 16px, body copy 17px, and small labels sit at 14px - the enforced floor
  (`scripts/enforce-min-font.mjs`).
- Motion lives in `src/styles/animations.css`; all effects respect `prefers-reduced-motion`.
- The theme is applied by an inline script in `<head>` before first paint to avoid a flash.

## Monthly reports

Monthly portfolio reports are published as normal site pages and exported to PDF from the
browser, rather than uploaded as static PDFs. Reports currently exist for May through November
2026 at `/en/reports/<month>-2026/` and `/th/reports/<month>-2026/`.

- Base report copy and figures live in `src/data/report-may-2026.ts`.
- Monthly variants and their reserve/supply snapshots are defined in
  `src/data/report-monthly.ts`. July 2026 records the 29 July export; November 2026 records the
  18 November import. Carried-forward months use the position they carry from.
- From the August 2026 report onward, reports do not disclose earlier vintage years. Older
  inventory is aggregated into one "Legacy" reserve line. July 2026 and earlier keep their
  reported vintage breakdown.
- From November 2026 onward, the reported reserve includes only the current vintage. Earlier
  vintages are excluded under the pool-freshness policy; the November 2026 report is the first
  2025-only reconciliation.
- The shared layout and A4 print styles live in `src/components/pages/ReportPage.astro`.
- Route files are dynamic `[slug].astro` wrappers in `src/pages/en/reports/` and
  `src/pages/th/reports/`.
- The "Download PDF" buttons call `window.print()`; the print stylesheet hides site chrome,
  puts the cover and key figures on page one, and renders the colophon as a back cover.

Add a month to the `MONTHS` list in `src/data/report-monthly.ts`; the route and reports index
update automatically.

## Redemption intake

The form on `/th/redeem/` and `/en/redeem/` posts to `POST /api/redemptions`, handled by
`src/worker.ts`. The Worker:

1. Validates the contact fields and the option-specific fields.
2. Re-verifies the transaction on Optimism (receipt logs) or Kubchain (token transfers).
3. Derives the amount from the REC transfer to the redemption vault (or a burn to zero).
4. Rejects used hashes, requests below 100 REC, cross-origin posts and basic spam.
5. Stores the request in D1 and returns a reference ID.

The browser performs the same on-chain check for immediate feedback; the Worker is authoritative.
The `/check/<address>` legacy deep link is a static redirect in `public/_redirects`
(`/check/*` -> `/th/check/?address=:splat`).

D1 schema: `migrations/0001_redemptions.sql`. Requests are stored even when no notification channel
is configured. To read them:

```bash
npx wrangler d1 execute rectoken-redemptions --remote \
  --command "SELECT id, created_at, contact_name, email, phone, option, amount, network, status FROM redemptions ORDER BY created_at DESC LIMIT 20;"
```

Optional notifications, configured as Worker secrets (never in source):

| Secret | Effect |
|---|---|
| `NOTIFY_WEBHOOK` | HTTPS endpoint receiving `{ "text", "content" }`; Slack/Discord-compatible |
| `RESEND_API_KEY`, `NOTIFY_EMAIL`, `FROM_EMAIL` | Transactional email via Resend |

No notification channel is configured in the current deployment. D1 and the Worker run on the free
plan; the email provider is optional. Set a secret with `npx wrangler secret put NOTIFY_WEBHOOK`.
No credentials belong in this repository.

See [`docs/backend-plan.md`](docs/backend-plan.md) for the intake model and notification options.

## Deployment (Cloudflare Worker + static assets)

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Node version | 22 |

`wrangler.toml` declares `main = "src/worker.ts"`, the `ASSETS` binding for `./dist`, and the `DB`
binding for `rectoken-redemptions`. `run_worker_first = true` lets the Worker answer `/api/*` and
fall through to `env.ASSETS.fetch()` for every page. `public/_headers` adds CSP and security headers;
`public/_redirects` preserves legacy routes (`/buy-sell` → `/th/trade`, `/privacy-policy` →
`/th/legal/privacy`, etc.) and the `/check/<address>` deep link.

Apply the D1 schema once per environment:

```bash
npx wrangler d1 execute rectoken-redemptions --remote --file=migrations/0001_redemptions.sql
```

To test the API and assets locally, build first and use Wrangler (not `astro preview`):

```bash
npm run build
npx wrangler dev --port 8788
```

`astro dev` and `astro preview` serve only the static site; `/api/redemptions` is unavailable there.

### Deliberate corrections from the legacy site
- “Tokenising carbon credits” → RECs are **not** carbon credits (Whitepaper §1.2).
- “CO2E Chain” → **ThaiFi** (chain 17) is the live deployment; the legacy CO2e chain is labelled
  as retired.
- The legacy CO2e contract `0x578f…` is separated from the live ThaiFi pool token `0x7269…`.
- The Kubchain bridge lock `0x18c8…` is a bridge contract, not a pool-token reference. The
  earlier site mislabelled it as a “whitepaper address”; the registry now labels it correctly.
- The old `/check` balance card was unreachable; it now works.
- The privacy policy placeholder `[insert email / contact channel]` is replaced with a real address.
- Native ThaiFi balance uses 6 decimals (pathUSD), not 18.
